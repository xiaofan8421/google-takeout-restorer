# Google Takeout 照片恢复器

把 Google 相册 Takeout 导出的**一堆散装文件**，还原成能直接导入相册的本地图库：按拍摄时间分年分层、Live Photo 不拆散、多台手机同名不覆盖。

Google 官方导出只负责把文件给你，不负责还原成相册。传统整理脚本大多「按文件名 + 按文件自身时间」硬塞目录，于是照片一到本地就散了。本工具针对这几件最烦的事做了修复。

## 一眼看懂：比传统工具好在哪

| 痛点 | 传统导出/整理工具 | 本工具 |
| --- | --- | --- |
| **Live Photo 被拆散**（最主要） | 静图和短视频各按自己的时间归档，视频常常没时间，结果一张照片一半进了 2023-06，另一半进了 `Unknown_Date`，导入相册后不再是一对 | 同目录同名同组绑定：短视频继承静图的拍摄时间与 GPS，落进**同一个年月目录、同一个主文件名**，只保留各自后缀 |
| 多台手机同名互相覆盖 | 每台手机都从 `IMG_0001` 重新编号，同名文件互相覆盖，只剩最后一个 | 用来源目录生成短哈希写进文件名，同名文件全部并存 |
| 年份层级目录丢失 | 输出一堆平铺文件，或者只剩 Google 自己的相册名，没有「年/年月」结构 | 读 JSON 里的拍摄时间，输出 `年/年-月/` 目录树 |
| `date-unknown` 乱丢 | 读不到时间的文件被塞进当天/当前月份，混进正常照片里 | 统一进 `Unknown_Date/`，不污染任何月份，同样带哈希防覆盖 |
| Google 截断文件名导致配不上 JSON | 长文件名被截断后匹配失败，时间全部丢失 | 多模式匹配：`文件名.json`、`名.json`、前缀截断模糊匹配 |
| 时间只写进文件名，系统里还是乱的 | 文件修改时间仍是解压时间 | 同步更新文件 mtime/atime；装了 `piexif` 还会写回 JPEG 的 EXIF |

## 痛点详解

### 1. Live Photo 配对分离（主要）

一条 Live Photo 本来是「一张静图 + 一段短视频」，常见是 `HEIC + MOV`。导出之后短视频经常**没有拍摄时间**，传统工具于是让它按自己的时间（解压时间或空时间）归档 —— 照片进了 `2023/2023-06/`，视频掉到 `Unknown_Date/`，导入相册时已经配不上。

本工具在同一文件夹内把**同名的图片和短视频绑成一组**：

- 短视频继承静图的拍摄时间和 GPS；
- 两者使用完全相同的目标目录和主文件名；
- 结果：`20230601_120000_IMG_0001_a1b2.heic` 和 `20230601_120000_IMG_0001_a1b2.mov`。

相册导入时会自动把这一对重新识别为 Live Photo。

### 2. 多台手机同名冲突

每台 iPhone/Android 都从 `IMG_0001` 重新编号。按文件名归档 = 后一部手机覆盖前一部，而文件名几乎一样，覆盖了也看不出来。

本工具对每个来源目录生成一段 4 位哈希（`get_path_hash`）写进文件名，不同手机、不同相册里的同名文件可以长期共存：

```text
20230601_120000_IMG_0001_a1b2.heic
20230601_120000_IMG_0001_c3d4.heic
```

### 3. 年份层级目录丢失

Takeout 里常常是平铺文件，或者只有 Google 自己的相册名。本工具读取 JSON 边车里的 `photoTakenTime`，输出成：

```text
2023/
  2023-06/
    20230601_120000_IMG_0001_a1b2.heic
    20230601_120000_IMG_0001_a1b2.mov
```

### 4. `date-unknown` 乱丢

读不到拍摄时间的文件不会散进错误的月份，而是统一收进 `Unknown_Date/`，并同样带上目录哈希避免同名覆盖。你的正常时间线不会被脏数据打乱。

## 快速开始

```bash
# 1. 解压 Takeout 压缩包，得到 Takeout/ 目录
# 2. 跑一次，看看结果
python3 google_takeout_restorer.py -i ./Takeout -o ./GooglePhotos_Restored
```

- `-i` 解压后的 Takeout 根目录
- `-o` 整理结果的输出目录
- **原文件不会被修改**，只做复制

可选：把拍摄时间写进 JPEG 的 EXIF（不装也能用，时间会写在文件修改时间上）：

```bash
pip3 install piexif
```

跑完会打印整理总数和成功配对的 Live Photo 视频数量。

## 文件名规则

```text
[拍摄时间]_[原文件名]_[目录哈希].[原后缀]
```

- 有拍摄时间：`20230601_120000_IMG_0001_a1b2.heic`
- 无拍摄时间：`IMG_0001_a1b2.heic`
- 同一条 Live Photo 的短视频与静图**主文件名完全相同**

## 支持格式

- 图片：`jpg` `jpeg` `heic` `png` `webp` `gif` `bmp` `tiff`
- 视频：`mov` `mp4` `m4v` `3gp` `avi` `mkv`

## 环境

Python 3.6+，只用标准库；`piexif` 为可选项。

## 说明

- 工具是**复制**而不是移动，跑之前不用备份，跑完确认无误再删原目录。
- Google 相册的「相册分组」不会保留，输出以**时间层级**为唯一组织方式（这也是最通用的相册导入结构）。
- 如果同一目录里存在多个前缀相同的 JSON，匹配策略取第一个命中的候选，极少数重名场景可能需要人工确认。
